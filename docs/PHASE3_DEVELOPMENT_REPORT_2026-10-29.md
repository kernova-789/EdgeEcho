# EdgeEcho 第三阶段开发报告：日常浏览与可测量回放

日期：2026-10-29，Asia/Shanghai；版本0.3.0。

## 已实现的用户流程

打开离线库 → 用日期时间或精确UTC微秒选区间 → 选择通道或XYZ同屏 → 缩放/平移定位 → 查询最近原始样本 → 播放或导出。新功能保持原库只读，不修改参考项目。

| 能力 | 当前行为与边界 |
| --- | --- |
| 日期时间 | 日历支持UTC/本地显示；额外0..999微秒余数保留毫秒以下精度。切换时区不改变查询UTC。显式拒绝夏令时缺口/重复时间；保留精确微秒输入处理极端边界。 |
| 曲线导航 | 滚轮以指针为中心缩放，左键框选，右/中键平移，单击seek，双击/Esc复位。每次范围变化重新请求原始数据降采样，不把已有包络当原始数据再次解释。 |
| XYZ比较 | 同一振动系列三轴共用时间与单位轴，颜色和图例区分。一次SQLite扫描后解码多个通道，请求共享记录数、解码值及输出字节预算。 |
| 精确读数 | 120ms悬停合并请求，后台读取可见区间原始记录，取最近good有限样本；显示样本时刻及与指针Δt，不插值、不查询包络代替原始值。长XYZ结果可在完整提示中查看。波形时间仍标为rate重建估计。 |
| 窗口缓存 | 最近最多3个窗口，估计结果字节不超过32MiB；缓存键含源身份、完整系列、通道、区间及分辨率。命中前后仍核对源。缓存是结果预算，不是Qt进程RSS硬上限。 |
| 预取 | 闲置时低优先级读取下一窗口。前台打开、seek、导出优先；旧任务取消并丢弃。最终窗口与前台采用相同范围计算，避免预取后不命中。 |
| CLI | 新增probe命令；给出完整时间界限时不必先全库统计。GUI与CLI均能输出当前版本及同一源码构建身份。 |

模块拆分：`app/plot_widget.*`处理图表，`app/time_range_editor.*`处理日历及DST，`Database::plots/probe`承担数据读取；窗口控制仍有进一步拆分空间。

## 实际回归

[统一验证](evidence/current-validation.json)：Linux Release 13/13入口、ASan/UBSan 9/9通过，Windows仅做交叉编译/PE检查。来源、预算、精确样本及多通道测试都是实际执行结果。

整窗GUI交互37项检查覆盖原有可靠性，以及日历微秒往返、XYZ渲染、滚轮重新查询、平移、复位、原始样本读数、缓存限制、源变化失效和预取命中。图表独立测试还检查接近9999年的微秒精度、1微秒缩放下限、三种颜色实际绘制和质量断线；日历独立测试显式覆盖纽约DST缺口/重复、1969本地对应合法UTC epoch、最大结束边界与无效区间。

关键回归：构造一个在min/max显示包络中被省略的样本，probe仍读出其原始值；XYZ合并结果逐点对照独立通道查询；组合解码超预算明确失败。

## 性能证据

最终100次重复基准、P50/P95和进程峰值RSS见[current-performance.json](evidence/current-performance.json)。工作负载沿用约237MiB合成库，含20万标量记录及819.2万新增波形样本。每次重复验证结果数量一致；源库哈希及源码指纹前后不变。

| 工作负载 | 次数 | P50 | P95 | 输出项数 |
| --- | --- | --- | --- | --- |
| 819.2万波形样本 | 100 | 638.768ms | 674.078ms | 3000 |
| 20万标量记录 | 100 | 722.168ms | 760.198ms | 4177 |
| 历史尾部1秒 | 100 | 0.660ms | 1.036ms | 100 |
| 10秒XYZ同屏数据 | 100 | 57.051ms | 64.463ms | 9000 |
| 10秒区间原始样本查询 | 100 | 27.982ms | 31.048ms | 1 |

五组基准同一进程峰值RSS为31,412KiB（约30.7MiB）。

这是单个离线连接的查询延迟，缓存未受控；不含GUI事件调度、绘制和进程启动。不得将查询P95直接解释为端到端seek P95，也不代表Windows、冷缓存或RK3588性能。

## 本轮没有宣称完成的事项

- 未找到可用于本轮验收的实际传感器振动/声音/特征捕获文件。演示、单测和Store写入兼容输入均标为模拟数据；固件.bin不是采集样本。
- 无Windows原生运行环境，没有WindowsGUI运行证据；交叉编译及CI配置不能替代。
- 没有执行8小时连续运行；百次大查询不等于长期稳定性验收。
- 全库overview仍执行精确分组和计数；初次打开超大库可能受15秒预算限制。当前结果缓存和预取不解决首次目录成本。
- 尚无FFT、音频设备输出、不同单位多指标叠画、跨传感器严格同步或原始记录按时序投递服务。

## 下一阶段的建议顺序

1. **双平台交付实机闭环**：Windows原生构建、运行、中文路径、100%/150%/200%DPI及无开发环境包；Linux至少一个干净镜像。所有证据绑定相同源码身份。
2. **真实数据回归包**：使用已确认来源的离线副本，按传感器/端口保留原始字节哈希、时间/质量/rate/单位依据及独立解码结果。不同传感器不能仅凭相同名称视为同一设备或同步时钟。
3. **大历史目录**：拆分轻量可用目录与精确统计，增加独立于原库的身份缓存；测试100万、1000万记录和较多系列/事件。不能只提高超时后宣称性能改善。
4. **长期与端到端测量**：记录打开到首帧、seek到首帧、取消、绘制时间、连续播放等待及RSS，安排8小时运行。界面测试驱动再逐步迁出主窗口。
5. 采样时钟、scale与校准契约齐备后，再单独安排FFT、音频输出和多传感器对齐；在线模式先设计一致快照交接，保留当前WAL拒绝策略。

## 建议验收目标

以下是下一阶段目标，不因本轮核心查询较快就自动判定通过。性能目标需固定硬件、输入数据与缓存条件，P95至少100次测量。

| 指标 | 建议目标 | 本轮证据范围 |
| --- | --- | --- |
| 原始数据一致性 | 无重漏；字节/ID/时间/质量一致；源库零写入 | 自动回归及模拟数据通过，真实采集输入待验 |
| 导出 | 同名最多一个成功；已有目标不变；取消无正式半文件 | 自动回归通过，掉电待专项 |
| 小窗口seek到首帧 | P95≤250ms | 已测核心查询；端到端GUI仍需计时 |
| 819.2万样本曲线查询 | P95≤1秒、核心基准RSS≤64MiB | 查实际[current-performance.json](evidence/current-performance.json)，不套用于GUI总内存 |
| 百万记录/约1GiB首次可用 | ≤5秒，精确统计允许后台进行 | 未建立该规模基线 |
| 本地读取/导出取消 | P95≤500ms；关闭≤2秒 | 有功能回归，尚未完成100次端到端测量 |
| 长期运行 | 8小时无崩溃；预热后内存无持续增长 | 未执行8小时验收 |
| 平台运行包 | Windows/Linux各至少一个无开发环境系统通过 | 当前Linux同机迁移通过结果见包报告；其余待验 |
