# EdgeEcho 第二阶段开发报告：可靠性与交付收尾

日期：2026-10-29，Asia/Shanghai。本文按当前0.3.0最终源码重新验收第二阶段任务；0.2历史构建及旧报告不作为本轮通过证据。

## 实施结论

源会话绑定、可靠导出和真实控件回归已完成，本机Linux验证已闭环。Windows核心和CLI已完成当前源码交叉编译，原生Windows桌面运行及干净Windows环境交付仍未验收。第三阶段的浏览功能同时已实现，见[第三阶段报告](PHASE3_DEVELOPMENT_REPORT_2026-10-29.md)。

## 已完成工作

| 原任务 | 实际实现与验收 |
| --- | --- |
| A1 源身份 | 绑定canonical path、SQLite database_id/generation、文件大小/mtime及平台文件标识。即使克隆数据库ID/大小/mtime相同，路径替换也会拒绝；缓存命中仍重新检查源身份。发现变化后清空旧记录、曲线及缓存，要求明确重开。 |
| A2 交互 | 时间轴拖动、轨道点击、键盘Home/End/Page/方向键、播放暂停停止、倍速、快速切换、取消、记录续页、源替换和重开恢复纳入真实Qt事件测试。 |
| A3 导出 | 私有排他临时文件、分块写、完成后不覆盖发布；进度含条数及字节，支持取消。默认30分钟总任务时限，各页查询仍有15秒预算。发布前观察者失败会清理；成功发布后观察者异常不能撤销已完成文件。演示库创建也采用同类发布流程。 |
| A4 Windows | 新增文件身份与原子文件适配随当前核心一并交叉编译；Windows原生Qt/MSVC与实际运行由工作流配置承接，本机不声明通过。 |
| A5 独立包 | Linux运行包收集Qt与非基础运行库、平台插件、许可、文档及SHA256清单，去除开发机RPATH。包校验复制到中文空格目录、清除开发环境查找路径，并核对GUI/CLI/manifest与源码身份。Windows提供windeployqt脚本。 |

文件操作适配集中在 `src/source_identity.cpp`、`src/atomic_output.cpp`。其余核心使用标准C++17/SQLite；没有引入epoll或Linux设备采集依赖。

## 本轮解决的实际问题

1. 原0.1报告、后续程序和生成头存在构建身份不一致。增加统一验证器，依据完整源码、测试与构建工具指纹校验所有配置；GUI、CLI和包混装旧版本会被拒绝。
2. 记录表逐格填充时，实时ResizeToContents重复扫描整页并触发字体布局，整窗交互回归曾超过时限。调试栈定位到populateRecords，现已批量更新并仅抽样32行测量列宽，保留手动调整。
3. GUI测试运行前删除旧JSON，防止失败后遗留的passed文件被误认为新结果；增加阶段日志定位卡点。

## 当前验证

[统一验证结果](evidence/current-validation.json)是本轮选定证据：Release 13/13入口通过，ASan/UBSan核心与CLI 9/9通过；均无跳过，使用新生成JUnit结果。输入源码在验证前后保持一致，程序输出同一版本和构建标识。

Windows交叉构建检查CLI及数据库、编码、会话、导出、浏览测试PE格式和x86-64架构；不执行这些程序。不能把此结果解释为Windows运行通过。

[原存储库兼容检查](evidence/current-compatibility.json)再次使用未修改的EdgeSense Replay Store写出3000条模拟标量记录和1个事件。分页、元数据、事件及曲线检查通过，参考项目37个构建/源码文件指纹不变。它不是物理传感器采集验收。

最终Linux包的实际迁移运行结果另见[current-package.json](evidence/current-package.json)。仅证明本机兼容ABI上的独立运行，不证明旧版Linux或干净系统镜像兼容。

## 第二阶段仍保留的交付条件

- Windows原生GUI运行、文件对话框、DPI缩放和独立包验收。
- Linux干净镜像、不同发行版和图形驱动验证；本机offscreen测试不能替代全部桌面环境。
- 强制退出、介质故障与真实掉电的专项试验；目前单测覆盖竞争、取消和可捕获失败，不宣称已做掉电验证。
