# EdgeEcho 开发报告与下一步开发建议

日期：2026-10-29（Asia/Shanghai）  
当前版本：0.1.0  
报告性质：首版实现复盘、现状评估与下一阶段开发路线。

## 1. 当前结论

EdgeEcho 已形成可在本机 Linux 上运行的离线数据回放首版：可以打开 EdgeSense Replay 的 v3 数据库，选择传感器、指标和通道，查看标量、振动、声音及特征曲线，并完成暂停、倍速、跳转、事件检查和原始记录导出。

核心采用 C++17、SQLite，桌面界面采用 Qt6。图形界面与命令行共享核心，没有运行时依赖相邻 EdgeSense Replay 源码，也没有引入 epoll 等 Linux 专属调度接口。

**当前应定位为“已验证的 Linux 离线回放首版，具备跨平台源码与 Windows 命令行交叉构建结果”。Windows 桌面程序的原生构建、实际运行和独立分发仍是下一阶段的交付门槛。**

建议下一步先完成正确性与双平台交付闭环，再扩展多曲线、长历史浏览和分析功能。在线读取、FFT、音频播放可以作为后续独立阶段。

### 4.2 性能测量

已有测量环境：Linux x86_64、AMD Ryzen5 4600U，合成数据库248,623,104字节，共200,310条记录，1500个显示时间桶。

| 工作负载 | 输出 | 曲线生成耗时 | CLI进程总时长 | 单进程峰值RSS |
| --- | --- | --- | --- | --- |
| 8,192,000波形样本 / 250块 | 3000点 | 509.54ms | 0.83s | 30,608KiB |
| 200,000标量记录 | 4177点，含断点 | 549.58ms | 0.85s | 21,784KiB |
| 历史尾部1秒 / 100条 | 100点 | 0.787ms | 0.29s | 21,716KiB |

这些结果说明：当前工作负载下，曲线生成和内存占用可以控制在较小范围；末端跳转没有退化为完整历史读取。曲线耗时不包含全部打开和目录统计成本，不能拿0.787ms解释成完整应用启动时间。

测量缓存未受控；结果不代表冷缓存、多十GB历史库、Windows或RK3588实机表现。原始报告包含源码、程序和数据库指纹，见 [performance.json](evidence/performance.json)。

## 5. 当前约束与需要优先解决的问题

### 5.1 Windows交付还没有完成实际闭环

目前有共用源码、交叉构建结果和CI配置，但没有 Windows Qt桌面实际运行记录。CMake 安装规则主要安装可执行文件和少量文档；工作流上传的是日志与截图，没有形成包含 Qt运行时及平台插件的最终分发包。

下一步需要原生构建、部署依赖、在没有开发环境的 Windows 上验证。该项是平台交付缺口，不是已证实的 Windows源码缺陷。

### 5.2 离线读取约束仍然必要，跨任务会话身份还可加强

`Database` 只接受停止写入并完成 checkpoint 的离线库，使用 immutable 只读打开，拒绝非空WAL及回滚日志。大小与mtime检查用于发现误用，不能充当活跃库一致性机制。

单个 Database 实例内部有只读事务和高水位；GUI的打开、窗口读取、记录续页和导出各自新建实例。若用户在两次任务之间替换同一路径的数据库，现有逻辑没有把后续任务绑定到最初打开的数据库身份。下一步应引入会话标识及源身份复核，发现变化后要求明确重开；这仍属于离线模式加固，不自动扩大为边采集边回放。

依据：`database.cpp` 的 `Database::Impl` / `check_source`，`app/main.cpp` 的 `openPath`、`loadWindow`、`loadPage`、`exportCsv`。

### 5.3 导出需要独立的长任务与文件发布流程

当前导出使用整项操作15秒预算，直接创建最终CSV，逐页写入；可捕获的错误会尝试删除输出。这对短导出有效，但长时段、大BLOB导出可能先遇到时限，也没有进度与安全续传。

源码采用“检查目标不存在，再用ofstream打开”的顺序，两步之间没有独占创建保障；程序被强制结束时也可能留下使用正式文件名的不完整CSV。建议改为受控临时文件、独占创建、不覆盖已有目标的完成发布流程，并将导出进度、取消和专用任务预算从交互查询中分离。

依据：`src/database.cpp` 的 `Database::export_csv`，当前第371—398行。该项来自静态代码审查，本轮没有做并发创建或强制退出实验。

### 5.4 桌面交互距离方便分析仍有提升空间

当前起止时间以UTC微秒输入，精确但不便于日常定位；图上主要支持单击跳转，缺少框选缩放、平移和精确值读数。单曲线可以切换不同系列，却不便于同时比较XYZ或同设备多指标。

时间轴当前只将 `sliderReleased` 连接到跳转逻辑，键盘或步进动作是否能正确改变播放位置，需要补充真实控件回归。应把它列为待复现的交互问题，不用内部 smoke 已通过来代替验证。

### 5.5 大历史库打开和连续播放仍需扩展验证

`overview` 每次精确执行GROUP BY、count和时间范围统计，结果条数有界不等于扫描成本有界；超大库可能在首次打开时触及15秒预算。CLI多个命令也先调用overview，即使用户已给出完整筛选与时间区间。

GUI目前窗口越界后再请求新数据，尚无相邻窗口预取与缓存；因此曲线查询快不等于高速连续播放不会等待数据。下一步应分别测量目录发现、窗口读取、解码、绘制、等待和取消时间，再决定优化位置。

### 5.6 测试和接口还需覆盖更丰富的输入组合

目前主要兼容目标是schema v3；同一系列中混合编码、编码变化、重叠波形及源文件替换，需要更明确的显示和失败策略。默认非重叠分页已针对时间下界优化；公开 `page(overlap=true)` 与波形预读的索引路径不同，需要单独测量，不应推断所有重叠查询都具有相同复杂度。

默认限额为单条8MiB、单页16MiB/512条、曲线25万记录/1000万样本、4096系列、15秒操作。它们控制资源，但不是已验证的最大可用数据库规模；桌面程序目前也没有提供这些预算的配置入口。

## 6. 下一步开发路线与验收标准

以下为建议顺序和候选版本范围，不是已开始实施或已经完成的功能。

### 阶段A：正确性补强与双平台可交付版本

建议作为下一轮的唯一主目标，优先级P0。

| 任务 | 具体改动方向 | 完成标准 |
| --- | --- | --- |
| A1 会话身份 | 打开时记录源身份，后续窗口/分页/导出验证同一来源；源变化后终止并要求重开 | 在两页或两个窗口之间替换同路径数据库时，不混入新文件数据；原库不产生写入 |
| A2 交互回归 | 覆盖时间轴鼠标拖动、单击、键盘、倍速、停止重播、快速切换和取消 | 控件位置与PlaybackClock一致；过期任务不覆盖新选择；错误状态可恢复 |
| A3 导出发布 | 独占临时输出、完成后发布、进度/取消、专用导出时间策略 | 成功文件可完整读取；取消/写失败不留下冒充成功的正式文件；已有目标不被覆盖 |
| A4 Windows桌面 | 在Windows原生Qt/MSVC环境构建、部署并执行核心/GUI测试 | 提供真实构建日志、测试退出码、GUI截图；中文/空格路径与100%/150%/200%缩放正常 |
| A5 独立分发 | 生成Windows压缩包和Linux运行包，包含匹配的依赖、插件、文档与许可 | 在没有本项目.deps和开发工具的目标环境启动；程序可报告版本及构建身份 |

A1—A3是建议先落地的代码任务；A4可并行验证源码与平台适配，A5依赖A4通过。若Windows运行环境暂不可用，应如实保持验收项未完成，同时推进前三项。

### 阶段B：日常回放体验与真实数据回归

优先级P1，在阶段A形成稳定基线后实施。

| 任务 | 建议方向 | 验收标准 |
| --- | --- | --- |
| B1 时间选择 | 日期时间输入、明确时区、常用区间、保留精确微秒入口 | 日期与微秒往返一致；半开区间和时区转换不改变原始timestamp |
| B2 曲线操作 | 框选缩放、平移、复位、悬停/双游标读数；需要精确样本时重新查询原始数据 | 缩放后原始峰值可核对，读数不会把min/max显示点误认为全部原始样本 |
| B3 多通道比较 | 先实现同系列XYZ共享时间轴，再扩展多指标分面 | 不混合不同单位；不自动把不同传感器视为严格同步；缺失与估计时间标识保留 |
| B4 数据回归包 | 使用真实采集文件的脱敏副本，覆盖振动、声音、特征、未知编码和非好质量 | 原始字节、记录ID、时间、质量与独立解码结果一致；Linux/Windows运行同一组输入 |
| B5 混合编码 | 在系列下显示编码/采样配置分段，允许明确选择兼容子集 | 支持的子集可查看；不兼容段有明确原因，不因单段问题伪装成全区间无数据 |

B4要区分“真实传感器采集数据”与“使用真实Store写出的模拟记录”，分别保留来源、哈希和验收结果。

### 阶段C：长历史和高速连续浏览

优先级P1/P2，以性能测量决定实现次序。

1. 拆分轻量目录发现与精确统计；为离线文件增加保存在EdgeEcho数据目录的缓存，按数据库身份及文件指纹失效，不向原库添加索引或表。
2. 预取相邻窗口，限制缓存字节和窗口数量；新seek立即取消旧预取。缓存键包含源身份、系列、通道、区间与显示分辨率。
3. 让绘图桶数跟随实际视口，而不是始终固定1500；扩大区间时保留尖峰、缺失边界和时间来源标识。
4. 增加100万/1000万记录、较多系列、较多事件、跨起点大块、混合质量和长期反复seek基准。

建议验收指标：固定说明CPU、存储、Qt/编译模式与缓存条件；分别记录首次打开、首帧、seek至首帧、连续播放等待、P50/P95延迟、取消耗时和峰值RSS。以相同工作负载对比当前基线，不能仅提高超时和内存上限后宣称性能改善。

### 阶段D：按实际需要扩展在线与分析能力

优先级P2/P3，应分别设计输入契约。

- **在线查看**：先设计一致快照的生成、校验、交接和切换，再考虑刷新节奏；不能直接删除WAL检查并继续使用immutable读取活跃库。在当前目录修改边界内，可先实现已有正式备份的导入；若确需更改上游存储项目，作为独立任务安排。
- **原始记录定时投递**：若后续需要把历史数据按时间交给算法或设备模拟器，新增ReplaySession及有界输出队列，定义积压、倍速、暂停和seek后的清空语义。当前PlaybackClock只驱动位置，不承诺逐条投递所有原始记录。
- **FFT/频谱与声音播放**：先确认采样率、通道、块间连续性、质量和输出标度；声音播放再处理缓冲、欠载、倍速与设备格式。
- **物理量与多传感器对齐**：校准比例和时钟依据必须来自可靠采集元数据；未知值保持未知，不由count或主机接收时间推断。

## 7. 推荐的下一轮具体范围

建议下一轮命名为“EdgeEcho 0.2：可靠回放与双平台交付”，只承诺以下可检查成果：

1. 完成源会话身份检查、时间轴真实交互回归和CSV完成发布流程。
2. 将现有Unicode/坏库/WAL检查纳入统一自动化，并补充源替换、取消、写失败与过期任务场景。
3. 完成Windows原生桌面验证和独立运行包；保留Linux当前通过的功能、只读与性能基线。
4. 交付新的实际验证报告，包含构建指纹、输入哈希、测试结果、平台差异与未完成项。

该轮建议暂不同时加入FFT、音频设备输出、云服务和复杂多传感器同步，以免在平台交付和基本交互尚未闭环时扩大验收范围。

## 8. 后续开发应保持的工程约束

- 继续以C++标准库、SQLite、Qt表达跨平台逻辑；不可避免的平台差异集中到小型适配层。
- 核心、数据库访问、会话控制、图表、后台任务与窗口布局逐步拆分；`app/main.cpp`不再持续承担全部新功能。
- 不改写原始记录、质量或诊断历史；原始导出与屏幕降采样始终分开。
- 新增缓存、会话文件与验证数据保存在EdgeEcho目录或用户明确选择的输出位置，保持参考项目只读。
- Windows原生运行、交叉编译、Linux测试、真实采集数据和合成性能测试分别记录，不相互替代。
- 当前目录尚不是Git仓库；后续建立版本管理和发布流水线时，应排除.deps、构建目录及数据库，并为程序加入可追溯的版本/构建标识。本文不执行建库、提交或上传操作。
